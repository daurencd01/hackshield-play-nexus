# 🛡️ HackShield Play Nexus

**HackShield Play Nexus** — это геймифицированная веб-платформа для обучения основам кибербезопасности. Проект погружает пользователя в роль "кибер-оперативника", который должен расследовать инциденты, принимать решения в различных сценариях (например, атаки программ-вымогателей, фишинг, защита инфраструктуры) и зарабатывать опыт (XP) для повышения своего ранга.

---

## 🎯 Для чего нужен этот проект?
Проект создан как интерактивный тренажёр, чтобы:
1. Обучать правильным действиям в случае кибератак.
2. Тестировать знания сотрудников или студентов в игровой (визуально-киберпанковой) форме.
3. Отслеживать прогресс обучаемых через систему достижений и лидерборд (Арена).

---

## 🏗️ Архитектура и Стек Технологий

Проект построен как современное **Single Page Application (SPA)** на базе экосистемы React.

- **Ядро:** React 18, TypeScript, Vite (сборщик).
- **Роутинг:** `react-router-dom` (управление навигацией по страницам: Хаб, Миссии, Арена и т.д.).
- **Стилизация:** Tailwind CSS + кастомные CSS переменные. Дизайн стилизован под киберпанк/хакерскую тематику с неоновым свечением и глитч-эффектами.
- **Компонентная база:** Использован UI-фреймворк `shadcn/ui` (построен на Radix UI) для доступных и легко настраиваемых базовых компонентов (кнопки, прогресс-бары, карточки).
- **Анимации:** `framer-motion` (отвечает за плавное появление элементов, реакцию интерфейса на курсор, анимации сценариев).
- **Иконки:** `lucide-react`.

## 💻 Как устроен движок Миссий (`ScenarioPlayer`)

Самая интересная часть функционала — прохождение миссий:
1. Пользователь заходит на `MissionPlayPage`.
2. Подгружается объект сценария из `mockData.ts`.
3. Запускается компонент `ScenarioPlayer.tsx`. Он поэтапно показывает шаги (диалоги, логи терминала).
4. На этапе `situation` пользователю предлагается сделать выбор.
5. Правильный выбор даёт больше XP: `isOptimal: true`.
6. Очки суммируются и по завершении засчитываются в общий профиль. 

*(Примечание: В текущей версии backend отсутствует. Данные не сохраняются при перезагрузке страницы, так как всё живёт внутри mockData.ts. Для превращения проекта в боевой продукт следует подключить реальную базу данных (например, Supabase/Firebase) и переписать mockData на API стейты).*

## 🚀 Как запустить и использовать локально

Так как проект использует `vite`, его можно запустить как стандартными средствами Node.js (через `npm`), так и более быстрым `bun` (соответствующие lock-файлы присутствуют).

### Вариант 1 (NPM)
1. Установите зависимости:
```bash
npm install
```
2. Запустите сервер разработки:
```bash
npm run dev
```

### Вариант 2 (Bun)
1. Установите зависимости:
```bash
bun install
```
2. Запустите проект:
```bash
bun run dev
```

После запуска в консоли появится адрес локального сервера, обычно это:
**`http://localhost:8080`**

### Сборка для продакшена (Deploy)
Чтобы собрать минифицированную версию приложения для загрузки на хостинг (Vercel, Netlify и др.):
```bash
npm run build
```
Итоговая сборка появится в папке `dist/`.
